At a glance

One-hot encoding Geography and Gender

X is not ready yet: Geography and Gender hold text. Each has only a few categories, so one-hot encoding is a good fit, done with scikit-learn's encoder or with pandas' get_dummies, whichever you prefer. Krish uses get_dummies and calls this step feature engineering.

pd.get_dummies(X['Geography']) makes one 0/1 column per country, France, Germany and Spain. A row gets 1 in the column of its own country and 0 in the others. With drop_first=True the first column is dropped and only Germany and Spain remain. Nothing is lost: a customer with Germany = 0 and Spain = 0 must be from France, so two columns represent all three countries. Gender becomes a single column, Male.

Next the original text columns are removed with drop. The argument axis=1 matters: it drops columns, where axis=0 would mean rows 3:43:32. Finally pd.concat joins X and the dummy columns side by side, again with axis=1. Krish runs the concatenation once without assigning it, checks that Germany, Spain and Male appear at the right end 3:45:40, and only then writes the result back to X.

Cell 4 · feature engineering
# Feature engineering: one-hot encode the categorical columns
geography = pd.get_dummies(X['Geography'], drop_first=True)   # Germany, Spain
gender = pd.get_dummies(X['Gender'], drop_first=True)         # Male

# Drop the original text columns (axis=1: columns, not rows)
X = X.drop(['Geography', 'Gender'], axis=1)

# Concatenate the dummy columns, again column-wise
X = pd.concat([X, geography, gender], axis=1)
X.head()

Not in the video: get_dummies orders the categories alphabetically, so drop_first removes France and Female. Keeping all the columns would give a set that sums to 1 in every row, a redundancy known as the dummy variable trap, which matters most for linear models. In pandas 2.x the dummy columns are booleans; pass dtype=int if you want 0 and 1.

3:47:49 interview question 3:49:26 the answer 3:50:30 StandardScaler 3:53:44 data leakage

Feature scaling, and which algorithms need it

One step is essential before an ANN sees the data: feature scaling. Krish flags a common interview question here. For which algorithms is feature scaling required: an ANN, linear regression, logistic regression, a decision tree, a random forest? His answer:

AlgorithmScale the features?Reason given in the video
ANNYesTrained by gradient descent and other optimizers; scaled inputs make convergence quicker.
Linear and logistic regressionYesAlso fitted with gradient descent, so the same reason.
Distance-based methods (for example KNN, K-means)YesThey compute distances, and large values make the calculation slow.
Decision tree, random forest, AdaBoost, XGBoostNoTree-based methods do not need it.

Not in the video: the usual reason for distance-based methods is that a feature with a large range, such as an account balance, dominates the distance and drowns out a feature like the number of products. Trees split on one feature at a time at a threshold, and rescaling a feature just moves the threshold, so the splits they find do not change.

For the scaler itself he picks StandardScaler 3:51:00. It applies the z-score from statistics to each column, so every feature ends up centred on its mean, with spread measured in standard deviations. MinMaxScaler would also work; it squeezes values into the range 0 to 1 (or −1 to 1), and Krish says to use it for CNNs, which come in the next session.

\[ z = \frac{x - \mu}{\sigma} \quad \text{(StandardScaler)}, \qquad x' = \frac{x - x_{\min}}{x_{\max} - x_{\min}} \quad \text{(MinMaxScaler)} \]

Here \(\mu\) and \(\sigma\) are the mean and standard deviation of that column. The difference between fit_transform and transform is another favourite interview question 3:52:05. fit_transform on the training set learns \(\mu\) and \(\sigma\) for each column and scales the training data with them. transform on the test set reuses those same training values. Fitting the scaler on the test data as well would cause data leakage: information from the data meant to be unseen would flow into the preprocessing, and the test score would no longer be an honest estimate.

Cell 6 · feature scaling
# Feature scaling
from sklearn.preprocessing import StandardScaler
sc = StandardScaler()
X_train = sc.fit_transform(X_train)   # learn mean and sd on the training set, then scale it
X_test = sc.transform(X_test)         # reuse the training mean and sd

X_train.shape                         # (8000, 11)

He adds that all of this is still feature engineering: choosing an ANN does not remove the need for it, and the same problem could also be solved with classical machine learning.

Not in the video: that warning appears when the scaler is fitted on a NumPy array and then given a DataFrame, for example when the fit_transform line runs a second time and X_train is already an array. It does not change the result here.

3:54:19 3:55:26 Keras as a wrapper

TensorFlow and Keras

Part two of the notebook builds the ANN, and Krish first places the two libraries. TensorFlow is a popular deep learning library open-sourced by Google; PyTorch, from Facebook, can do the same things. Keras is a wrapper around TensorFlow: it offers simple functions that call TensorFlow's APIs underneath, so you can build a network without writing the low-level code.

Before TensorFlow 2.0 the two were separate. You installed TensorFlow, then Keras, and the versions had to match. From 2.0 on, Keras is integrated into TensorFlow as tf.keras, so one installation is enough. That is why the version check in the first cell mattered.

Krish credits a Google DeepMind team with creating TensorFlow. It was in fact developed by the Google Brain team and released in 2015.

Sequential, Dense, activation layers and Dropout

Everything the network needs comes from tensorflow.keras. Besides Sequential and Dense, Krish shows that tensorflow.keras.layers also offers the activation functions from Part 4 as layers, such as LeakyReLU, PReLU, ELU and ReLU, and he imports Dropout.

Cell 7 · Keras imports
# Part 2: now let's create the ANN
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense
from tensorflow.keras.layers import LeakyReLU, PReLU, ELU, ReLU
from tensorflow.keras.layers import Dropout

Not in the video: the model below uses activation names such as 'relu', so these activation layers are never needed. To use one, add a Dense layer without an activation and put the activation layer after it, for example classifier.add(Dense(7)) followed by classifier.add(LeakyReLU()).

To explain the pieces he sketches a network 3:59:08: 11 inputs, a couple of hidden layers, and a single output that says 1 or 0, since the problem is binary. Every neuron in one layer connects to every neuron in the next.

  • Sequential treats the whole network as one block. Once it is built, that block can run forward propagation and backward propagation.
  • Dense creates the neurons, the circles in the sketch: a fully connected layer. Krish uses it for every layer, input, hidden and output.
  • Activation functions (ReLU, PReLU, sigmoid, tanh, and so on, covered in depth earlier) are applied inside the hidden layers.

Not in the video, a more precise picture: Sequential is a linear stack of layers in which each layer's output is the next layer's input. Forward propagation, the loss, backpropagation and the optimizer's weight updates all run when you call fit; see Part 2 for how they work. A Dense layer with weight matrix \(\mathbf{W}\) (shape inputs × units), bias \(\mathbf{b}\) and activation \(g\) computes \(\mathbf{h} = g(\mathbf{W}^\top\mathbf{x} + \mathbf{b})\). For the IIT Madras treatment, see Lecture 4 (lecture-04.html).

Dropout

A deep, densely connected network can solve complex problems: forward and backward propagation, the loss and the optimizer together push the weights toward a minimum. Sometimes the network overfits instead 4:02:24: accuracy on the training data is very high, but accuracy on the test data drops. A dropout layer reduces overfitting. Krish compares it to the L1 and L2 regularization of his machine learning sessions.

A dropout ratio of 0.3 on a layer means that 30% of that layer's neurons are deactivated while training 4:02:56. With 0.5, half of them are. The neurons are chosen at random. A deactivated neuron behaves like a dead neuron for that pass: its connections are cut, and forward and backward propagation run through the neurons that remain.

Not in the video: the Keras rate is the probability of dropping each unit, drawn afresh at every training step. During training Keras divides the kept outputs by \(1 - \text{rate}\), so at prediction time the layer simply passes its input through unchanged. Lecture 6 writes \(p\) for the probability of keeping a unit, the opposite convention. For the IIT Madras treatment, see Lecture 6 (lecture-06.html).

4:04:34 initialize 4:05:10 "input layer" 4:06:13 hidden layers 4:08:26 output layer

Building the network layer by layer

The ANN starts as an empty Sequential model called classifier, and layers are added one at a time with classifier.add.

  • "Input layer." X_train.shape shows 11 features, so Krish adds Dense(units=11, activation='relu'). He describes the ReLU as the activation that will be applied to the next layer.
  • First hidden layer: Dense(units=7, activation='relu'). He wavers between six and seven neurons; the exact number is up to you. There are techniques for choosing the number of hidden neurons, which he leaves for later.
  • Second hidden layer: Dense(units=6, activation='relu'). A Dense layer has other parameters as well, such as the bias settings 4:07:17. The activation can be given as a string in quotes or as the function itself.
  • Output layer: one neuron, because the problem is binary. He asks the audience for its activation and answers sigmoid.
Cell 8 · the network
# Let's initialize the ANN
classifier = Sequential()

# Adding the input layer
classifier.add(Dense(units=11, activation='relu'))

# Adding the first hidden layer
classifier.add(Dense(units=7, activation='relu'))

# Adding the second hidden layer
classifier.add(Dense(units=6, activation='relu'))

# Adding the output layer
classifier.add(Dense(1, activation='sigmoid'))

Two corrections. First, Keras has no Dense input layer. Dense(units=11) is a layer of 11 neurons that receives the 11 features; the input itself is implicit, and Keras infers its size the first time it sees data (or you can declare it with tf.keras.Input(shape=(11,))). So the network is 11 inputs → 11 → 7 → 6 → 1, with three ReLU hidden layers. Second, a layer's activation acts on that layer's own output, \(\mathbf{h} = \operatorname{relu}(\mathbf{W}^\top\mathbf{x} + \mathbf{b})\), and the next layer receives these activated values.

The sigmoid squashes the output neuron's score \(z\) into \((0, 1)\), so the output reads as the probability that the customer exits:

\[ \hat{y} = \sigma(z) = \frac{1}{1 + e^{-z}} = P(\text{Exited} = 1 \mid \mathbf{x}) \]

Sigmoid and ReLU are covered in Part 4; for the IIT Madras treatment, see Lecture 7 (lecture-07.html).

Krish does not count the parameters, but he does marvel at how many weights train in parallel when he prints them later. The count follows directly from the shapes.

Parameters of a Dense layer (not in the video) \[ \text{params} = \underbrace{n_{\text{in}} \times n_{\text{units}}}_{\text{weights}} + \underbrace{n_{\text{units}}}_{\text{biases}} \qquad 132 + 84 + 48 + 7 = 271 \text{ for the churn model} \]

Dropout layers have no parameters: they only zero some outputs.

4:08:57 4:09:29 learning rate 4:10:00 an Adam object

Compiling: optimizer, loss and metric

Before training, the network is compiled with three choices. The optimizer is Adam, which Krish calls the best optimizer. The loss is binary cross-entropy, because the target has two classes, as discussed in the loss-functions session. The metric to report is accuracy.

Cell 9 · compile
classifier.compile(optimizer='adam', loss='binary_crossentropy', metrics=['accuracy'])

For one training example with label \(y \in \{0, 1\}\) and predicted probability \(\hat{y}\), the loss is

\[ L(y, \hat{y}) = -\big[\, y \log \hat{y} + (1 - y) \log(1 - \hat{y}) \,\big], \]

averaged over the examples in a batch. Keras's accuracy metric counts \(\hat{y} \ge 0.5\) as a prediction of 1.

Where is the learning rate? To set it, create the optimizer as an object and pass that to compile instead of the string. Krish sets learning_rate=0.01. Any other optimizer under tf.keras.optimizers, such as SGD or RMSprop, can be used the same way, but he sticks with Adam.

Cell 10 · Adam with a chosen learning rate
import tensorflow
opt = tensorflow.keras.optimizers.Adam(learning_rate=0.01)
opt                              # an Adam optimizer object

classifier.compile(optimizer=opt, loss='binary_crossentropy', metrics=['accuracy'])

Krish says Adam's default learning rate is 0.01. In Keras the default is 0.001, so his explicit 0.01 is ten times the default. For Adam itself, see Part 5; for the IIT Madras treatment, see Lecture 5 (lecture-05.html). Binary cross-entropy is in Part 4 and Lecture 4 (lecture-04.html).

Training is one call to fit, whose return value Krish stores as model_history. Besides the training data it takes three settings.

  • epochs=1000, deliberately far too many, to set up the discussion of early stopping.
Cell 11 · first training run

# 536/536 [======] - loss: … - accuracy: … - val_loss: … - val_accuracy: …

The progress bar shows 536 iterations per epoch, and Krish asks why. The arithmetic: 8,000 training rows, of which 67% (5,360) remain after the validation split, in batches of 10.

\[ \text{steps per epoch} = \frac{8000 \times (1 - 0.33)}{10} = \frac{5360}{10} = 536 \]

Early stopping

Early stopping ends training automatically once the model stops improving. Krish searches for "early stopping keras", copies the example call from the Keras documentation into the notebook, and edits the values. In the documentation's words, the callback will “stop training when a monitored metric has stopped improving”. He sets a small min_delta, a patience and verbose=1, so that Keras prints a message when it stops.

Cell 13 · the EarlyStopping callback
# Early stopping (pasted from the Keras documentation, then edited)
import tensorflow as tf
early_stopping = tf.keras.callbacks.EarlyStopping(
    monitor='val_loss',
    min_delta=0.0001,            # illustrative: the value he types is not audible
    patience=20,                 # illustrative
    verbose=1,
    mode='auto',
    baseline=None,
    restore_best_weights=False,
)

What the arguments mean, following the documentation he opens:

  • monitor: the quantity to watch, here the validation loss.
  • min_delta: the smallest change that counts as an improvement.
  • patience: how many epochs without improvement to allow before stopping.
  • verbose: 1 prints a message when training stops.
  • mode: whether the quantity should go down ('min', for a loss) or up ('max', for an accuracy). 'auto' infers it from the name.
  • baseline: an optional value the metric must beat.
  • restore_best_weights: whether to go back to the weights of the best epoch at the end. With False, the model keeps the weights from the last epoch it ran.

The callback is passed to fit through the callbacks argument. That tells Keras to monitor the validation loss and stop the training when it no longer improves. When Krish runs it, classifier turns out to be undefined because the kernel had restarted 4:19:13, so he re-runs every cell from the top: data, encoding, scaling, model, optimizer, compile, callback, and then the new fit.

Cell 14 · training with early stopping
model_history = classifier.fit(X_train, y_train, validation_split=0.33,
                               batch_size=10, epochs=1000,
                               callbacks=[early_stopping])
# ...
# Epoch 00030: early stopping

He expects the accuracy not to go beyond about 87% anyway. Towards the end the validation loss starts to rise, and at epoch 30 Keras prints that it has stopped early, with the validation accuracy around 85%. Out of the thousand epochs requested, 30 were run.

  1. What EarlyStopping(monitor='val_loss') does after each epoch (Keras's rule, not spelled out in the video)
  2. Read the epoch's val_loss.
  3. If it is below the best value so far by more than min_delta, it is an improvement: record it as the best, reset the wait counter to 0, and (with restore_best_weights=True) remember the current weights.
  4. Otherwise add 1 to the wait counter. If the counter has reached patience, stop training.
  5. On stopping, keep the last epoch's weights, or put the remembered best weights back if restore_best_weights=True.

So training stops exactly patience epochs after the last improvement. If the patience had been 20, the stop at epoch 30 would mean the last improvement came at epoch 10. The demo below runs this rule on a synthetic pair of loss curves.

For the IIT Madras treatment, see Lecture 6 (lecture-06.html). Its version returns the model saved \(p\) steps before the stop, which in Keras corresponds to restore_best_weights=True.

Predictions, confusion matrix and accuracy

Now the test set. classifier.predict(X_test) returns the sigmoid output for each customer, a probability between 0 and 1. Comparing it with 0.5 turns it into a decision: a probability of 0.5 or more becomes True (predicted to exit), anything lower becomes False. Scikit-learn then builds the confusion matrix and the accuracy.

Cell 16 · evaluate on the test set
# Making the predictions and evaluating the model
y_pred = classifier.predict(X_test)     # probabilities, shape (2000, 1)
y_pred = (y_pred >= 0.5)                 # True = predicted to exit

# Make the confusion matrix
from sklearn.metrics import confusion_matrix
cm = confusion_matrix(y_test, y_pred)
cm

# Calculate the accuracy
from sklearn.metrics import accuracy_score
score = accuracy_score(y_pred, y_test)
score                                    # about 0.85 in the video

The confusion matrix has the true classes as rows and the predicted classes as columns. The video does not read its four numbers aloud; its layout is:

Predicted 0 (stays)Predicted 1 (exits)
Actual 0 (stayed)true negatives (TN)false positives (FP)
Actual 1 (exited)false negatives (FN)true positives (TP)
\[ \text{accuracy} = \frac{TN + TP}{TN + FP + FN + TP} = \frac{TN + TP}{2000} \]

Krish's score is about 85% 4:25:18, and he says you may get around 86% or 87%.

Not in the video: runs differ a little because the initial weights are random. Scikit-learn's signature is accuracy_score(y_true, y_pred). Swapping the arguments does not change accuracy, but it would swap precision and recall. Also, since roughly four in five customers stay, predicting "stays" for everyone would already score about 80%. The confusion matrix shows how many of the customers who left the model actually catches.

Last, he shows how to add the dropout layers he explained earlier. It takes a few tries on screen, which is instructive in itself. Passing dropout=0.3 inside Dense fails with "Keyword argument not understood", and classifier.add(Dropout=0.3) fails too. Key terms

Customer churn
Customers leaving a business. Here the target Exited is 1 if the customer left the bank, which makes a binary classification problem.
Independent and dependent features
The inputs X (columns 3 to 12) and the target y (column 13), split with iloc.
One-hot encoding
One 0/1 column per category of a text feature; pd.get_dummies in pandas.
drop_first=True
Drops the first category's column, so \(k\) categories need \(k - 1\) columns; the dropped category is the row of all zeros.
Feature scaling
StandardScaler: \(z = (x - \mu)/\sigma\) per column. MinMaxScaler: values into \([0, 1]\). Needed for ANNs, linear and logistic regression and distance-based methods.
Data leakage
Information from the test data influencing training. Avoided by fitting the scaler on the training set and only transforming the test set.
Sequential model
A Keras model that is a linear stack of layers; fit runs forward propagation, backpropagation and the weight updates.
Dense layer
A fully connected layer: \(\mathbf{h} = g(\mathbf{W}^\top\mathbf{x} + \mathbf{b})\), with \(n_{\text{in}} n_{\text{units}} + n_{\text{units}}\) parameters.
Dropout layer
During training, zeros each output of the previous layer with probability rate, chosen afresh every step; does nothing at prediction. Reduces overfitting; no parameters.
Binary cross-entropy
\(-[y\log\hat{y} + (1-y)\log(1-\hat{y})]\), the loss for a 0/1 target with a sigmoid output.
Validation split
The fraction of training rows fit holds out to report val_loss and val_accuracy after each epoch; 0.33 here.
Batch size, step, epoch
Rows per weight update; one update; one pass over the training rows. Here 536 steps of 10 rows make an epoch.
Early stopping
A callback that stops training once the monitored metric has not improved by more than min_delta for patience epochs.
History object
What fit returns; .history holds per-epoch lists of loss, accuracy, val_loss and val_accuracy.

Test yourself

Q1Which columns does dataset.iloc[:, 3:13] select, and why does the network end up with 11 inputs?

Positions 3 to 12, since a slice excludes its end: CreditScore, Geography, Gender, Age, Tenure, Balance, NumOfProducts, HasCrCard, IsActiveMember and EstimatedSalary, 10 columns. Positions 0 to 2 are a row counter, an ID and a surname, with no information about churn, and 13 is the target. Encoding removes Geography and Gender (8 left) and adds Germany and Spain from Geography and Male from Gender: \(8 + 2 + 1 = 11\).

Q2After pd.get_dummies(X['Geography'], drop_first=True), how are customers from France, Germany and Spain represented? Why is dropping a column safe?

Two columns remain, Germany and Spain. France is \((0, 0)\), Germany \((1, 0)\) and Spain \((0, 1)\). Every customer is in exactly one country, so the third column would always equal 1 minus the other two; it carries no extra information. (Not in the video: keeping it creates the dummy variable trap for linear models.)

Q3Why sc.fit_transform(X_train) but only sc.transform(X_test)?

fit computes each column's mean and standard deviation. They must come from the training data alone, and the test set must be scaled with those same values so both sets are on one scale. Fitting on the test data would let information from it leak into the preprocessing (data leakage), and the test score would stop being an honest estimate of performance on new customers.

Q4Which of these need feature scaling: an ANN, logistic regression, KNN, a random forest, XGBoost?

The ANN and logistic regression do, because they are trained by gradient descent, which converges faster on scaled inputs. KNN does, because it is distance-based. The random forest and XGBoost do not: they are built from trees, which split one feature at a time at a threshold, and rescaling a feature only moves the threshold.

Q5Count the trainable parameters of the 11-input network with Dense layers of 11, 7, 6 and 1 units. What changes if the first layer has 20 units, or if Dropout layers are added?

\(11 \cdot 11 + 11 = 132\), \(11 \cdot 7 + 7 = 84\), \(7 \cdot 6 + 6 = 48\) and \(6 \cdot 1 + 1 = 7\), so 271. With 20 units first: \(11 \cdot 20 + 20 = 240\), then \(20 \cdot 7 + 7 = 147\), then 48 and 7, so 442. Dropout layers add nothing; they have no weights.

Q6With 8,000 training rows and validation_split=0.33, how many steps does an epoch take with batch_size=10? With batch_size=32?

The split leaves \(8000 \times 0.67 = 5360\) rows to train on. With batches of 10 that is \(5360 / 10 = 536\) steps, the number in Krish's progress bar. With 32: \(5360 / 32 = 167.5\), so 168 steps, 167 full batches and a last one of 16 rows.

Q7Suppose EarlyStopping(monitor='val_loss', patience=20) prints "Epoch 00030: early stopping". When did the validation loss last improve, and which weights does the model hold?

Training stops when 20 epochs in a row bring no improvement, so the last improvement was at epoch 10 (epochs 11 to 30 are the 20). With the default restore_best_weights=False the model keeps the epoch-30 weights, whose validation loss is worse than at epoch 10. Setting restore_best_weights=True puts the epoch-10 weights back. (The patience Krish actually used is not audible; this is a what-if.)

Q8What does Dropout(0.3) placed after a Dense(10) layer do during training, and during predict?

At every training step each of the 10 outputs is set to 0 with probability 0.3, independently, so about 3 are off on average and a different set each time. The dropped units pass nothing on for that step, which keeps the network from relying on any single unit and reduces overfitting. Keras scales the kept outputs by \(1/0.7\) during training, so at prediction the layer passes everything through unchanged. It adds no parameters.
