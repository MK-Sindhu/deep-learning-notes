Optimizers: from gradient descent to Adam

Krish tells the optimizers as a story in which each one fixes a flaw of the one before: gradient descent needs too much memory, SGD is slow and noisy, mini-batches cut the cost but keep some noise, momentum smooths that noise with an exponentially weighted average, AdaGrad and RMSProp make the learning rate adaptive, and Adam combines smoothing with an adaptive rate. Along the way he defines epochs, batch size and iterations.

At a glance

  • An optimizer is the rule that updates the weights and biases during backpropagation so that the cost goes down. Every optimizer here starts from \(w_t = w_{t-1} - \eta\,\partial L/\partial w_{t-1}\) and changes either the gradient that goes into it or the learning rate \(\eta\).
  • Gradient descent uses all \(n\) records for each update, so one iteration is one epoch, and it needs a lot of memory. SGD uses one record per update: little memory, but \(n\) iterations per epoch, slow convergence and a very noisy path. Mini-batch SGD uses a batch (say 1,000 records), so an epoch takes \(n/\text{batch size}\) iterations, with less noise.
  • SGD with momentum steps along \(V_{dw}\), the exponentially weighted average of the gradients, \(V_{dw_t} = \beta V_{dw_{t-1}} + (1-\beta)\,\partial L/\partial w_{t-1}\), with \(\beta\) around 0.95. Most of the weight goes to the history, so the zigzag (noise) is smoothed out.
  • AdaGrad makes the learning rate adaptive, \(\eta'_t = \eta/\sqrt{\alpha_t + \epsilon}\) with \(\alpha_t\) the sum of all past squared gradients. The rate shrinks as training goes on, but \(\alpha_t\) can grow so large that the weights stop changing. AdaDelta and RMSProp replace the sum by an exponentially weighted average \(S_{dw}\), which keeps the rate under control.
  • Adam combines the two ideas, \(w_t = w_{t-1} - \eta\,V_{dw}/\sqrt{S_{dw} + \epsilon}\): smoothing from momentum, an adaptive rate from RMSProp. Krish calls it the best optimizer at present and the one most people use.

What an optimizer does

The session covers seven optimizers in order: gradient descent, stochastic gradient descent (SGD), mini-batch SGD, SGD with momentum, AdaGrad (adaptive gradient), RMSProp and the Adam optimizer, which Krish calls the best optimizer currently in use. Along with them come three training terms: batch, epoch and iteration. An ANN practical was to follow if time allowed; otherwise the ANN and CNN parts move to the next session, which is what happens.

Everything starts from the weight-update formula of backpropagation, which the earlier parts used throughout:

Weight update (gradient descent) \[ w_{\text{new}} = w_{\text{old}} - \eta\,\frac{\partial L}{\partial w_{\text{old}}} \]

\(\eta\) is the learning rate. The bias is updated the same way, \(b_{\text{new}} = b_{\text{old}} - \eta\,\partial L/\partial b_{\text{old}}\).

Plot the loss against a weight \(w\) and you get a bowl whose lowest point is the global minimum. Wherever the current weight is, the update moves it toward that point: if the slope is negative the weight increases, if it is positive the weight decreases. The learning rate sets how big each move is.

Where does the optimizer sit in the network? Take an input layer, one hidden layer and an output layer, all connected 2:38:07. Forward propagation multiplies the inputs by the weights, applies the activation functions and produces \(\hat y\). A loss function then compares \(\hat y\) with \(y\). Krish uses the mean squared error and corrects the version from the previous session, where he wrote \(\tfrac12\) and left out the \(n\) 2:39:15:

\[ \text{MSE} = \frac{1}{2n}\sum_{i=1}^{n}\big(y_i - \hat y_i\big)^2 \]

Backward propagation then updates every weight (\(w_1, w_2, w_3, w_4, \dots\)) and bias so as to minimize this loss 2:39:48. The method used for that update is the optimizer. Gradient descent is the first example.

Forward and backward propagation and the update rule are in Part 2, the chain rule in Part 3, and loss versus cost functions in Part 4. For the IIT Madras treatment of gradient descent, see Lecture 3 (lecture-03.html) and Lecture 5 (lecture-05.html).

2:40:19 epoch 2:40:51 a million records 2:42:29 disadvantage

Gradient descent: all records in every update

Before the optimizers, Krish defines an epoch. His first definition: one forward propagation plus one backward propagation is one epoch. Suppose the data set has a million records. In gradient descent all million go through forward propagation together. The network computes \(\hat y\) for every record, and the cost function sums over all of them:

\[ J = \frac{1}{2n}\sum_{i=1}^{n}\big(y_i - \hat y_i\big)^2, \qquad n = 1{,}000{,}000 \]

That is a million calculations of inputs times weights in one forward pass. Backward propagation then updates all the weights once, based on this cost. Because the whole data set goes through in one batch, one epoch of gradient descent is exactly one weight update. (Once SGD splits an epoch into several updates, an epoch becomes one pass of all the records through the network; for gradient descent the two definitions agree.)

The problem is resources 2:42:29. To push a million records through at once, in every epoch, you need a very large RAM, and for the parallel processing probably GPUs as well 2:43:00. The convergence itself is fine: on a big enough machine gradient descent heads straight for the global minimum. Krish calls the resource cost its major disadvantage, and asks whether another optimizer could work well with fewer resources.

Advantages

  • Uses the exact gradient of the full cost, so the path to the minimum is smooth.
  • Converges in few updates.

Disadvantages

  • Resource intensive: all records must be in memory for every update, which needs a huge RAM and often GPUs.
2:44:04 2:44:37 iterations 2:46:14 slow convergence

Stochastic gradient descent: one record at a time

In stochastic gradient descent (SGD) each forward and backward pass uses a single record. Pass record 1 forward, compute \(\hat y\) and the loss, and update the weights: that is iteration 1. Pass record 2 and update again: iteration 2. The epoch is now divided into iterations by data point. With a million records, one epoch takes a million iterations.

The update rule does not change. Only the loss inside it now comes from one record \(i\):

\[ w_t = w_{t-1} - \eta\,\frac{\partial L_i}{\partial w_{t-1}}, \qquad L_i = \tfrac12\big(y_i - \hat y_i\big)^2 \]

Deep learning models are usually trained for many epochs, say 100 (when to stop is the subject of early stopping, which comes later) 2:45:41. A hundred epochs of a million iterations each is 100 million iterations.

SGD solves the memory problem, since only one record is loaded at a time. Its major disadvantage is that convergence is very, very slow 2:46:14: every single record triggers its own backpropagation and weight update. Krish adds a second problem a little later 2:47:16: the time complexity is high, so although the resource constraint is solved, training takes long.

Advantages

  • Needs very little RAM: one record at a time.

Disadvantages

  • Convergence is very slow.
  • High time complexity: \(n\) updates per epoch, 100 million for 100 epochs of a million records.
  • The noisiest path of all, as the diagram at 2:50 shows (see Noise).
2:47:16 2:48:20 batch size 2:49:26 why it is better

Mini-batch SGD: a batch of records per update

The researchers' next fix is mini-batch stochastic gradient descent. Instead of one record at a time, choose a batch size, say 1,000. Each iteration passes 1,000 records forward and backward and updates the weights once. Iteration 2 takes the next 1,000, and so on until every record has been used, which completes the epoch.

Iterations per epoch \[ \text{iterations per epoch} = \frac{n}{\text{batch size}} = \frac{1{,}000{,}000}{1{,}000} = 1{,}000 \]

Krish lists three gains over the previous two 2:49:26. It is no longer as resource intensive as gradient descent, convergence is better than with SGD, and the time complexity improves, because a million iterations per epoch have become a thousand.

Advantages

  • Moderate memory: one batch at a time.
  • Better convergence than SGD.
  • Lower time complexity: \(n/\text{batch size}\) iterations per epoch.

Disadvantages

  • The path still zigzags; less than SGD, but the noise is there (next sections).

Not in the video: the cost of one update is averaged over the batch, \(J_{\text{batch}} = \frac{1}{2m}\sum_{i \in \text{batch}}(y_i - \hat y_i)^2\) with \(m\) the batch size. When the batch size does not divide \(n\), the last batch is smaller and an epoch has \(\lceil n/\text{batch size}\rceil\) iterations. Typical batch sizes are 32 to 256. For the IIT Madras treatment, see Lecture 5 (lecture-05.html), which covers stochastic and mini-batch gradient descent.

Epochs, batches and iterations side by side

The three terms the agenda promised, collected from the last three sections:

  • Epoch: one pass of all \(n\) training records through forward and backward propagation.
  • Batch size: how many records go into one forward pass and one weight update. It is \(n\) for gradient descent, 1 for SGD and something in between for mini-batch SGD.
  • Iteration: one forward pass on one batch, the cost, one backward pass and one weight update. An epoch has \(n/\text{batch size}\) iterations.

Noise: how the three paths differ

Krish draws the three optimizers heading for the global minimum. Gradient descent, which sees all records in every update, goes down smoothly. SGD jumps back and forth in a zigzag, because each update is based on a single data point and so points in a different direction each time. Mini-batch SGD zigzags less, since each update averages over a batch.

That zigzag movement is called noise 2:52:08. SGD has the highest noise, gradient descent the least, and mini-batch SGD very little, but some. Noise costs time: the more the path wanders, the longer it takes to reach the global minimum.

His analogy is a climber heading for a mountain peak 2:52:40. Walking straight up is fastest. Moving in big zigzags from one side to the other takes the longest. Small zigzags land in between. For an optimizer the peak is the global minimum.

So mini-batch SGD still has noise. How can it be removed? The answer is momentum 2:53:47.

2:54:22 2:56:04 exponentially weighted average 2:57:43 time-step notation

SGD with momentum: smoothing the journey

The fourth optimizer is SGD with momentum. The "SGD" here means mini-batch SGD: it is mini-batch SGD with a momentum term. Momentum smooths the path to the global minimum and reduces the noise. The smoothing comes from a moving average, more precisely the exponentially weighted average (also called the exponential moving average). Krish notes that this kind of average is also used in time-series models such as ARIMA and ARMA.

To make the averaging easy to write, he rewrites the update rule with time steps 2:57:43. The current step is \(t\) and the previous one \(t-1\), so \(w_{\text{new}}\) becomes \(w_t\) and \(w_{\text{old}}\) becomes \(w_{t-1}\):

\[ w_t = w_{t-1} - \eta\,\frac{\partial L}{\partial w_{t-1}}, \qquad b_t = b_{t-1} - \eta\,\frac{\partial L}{\partial b_{t-1}} \]

It is the same rule as before. The time index is what the average needs.

2:58:15 3:00:31 β as a hyperparameter 3:01:03 β = 0.95 3:02:38 V at time 3

The exponentially weighted average

Take a time series: at times \(t_1, t_2, t_3, \dots, t_n\) the values are \(a_1, a_2, a_3, \dots, a_n\). The weighted average \(V\) starts at the first value, and every later step mixes the previous average with the new value:

Exponentially weighted average \[ \begin{gathered} V_1 = a_1, \qquad V_2 = \beta V_1 + (1-\beta)\,a_2, \qquad V_3 = \beta V_2 + (1-\beta)\,a_3, \qquad \dots \\ V_t = \beta V_{t-1} + (1-\beta)\,a_t \end{gathered} \]

\(\beta\) is a hyperparameter between 0 and 1. It decides where the focus goes: on the previous average (large \(\beta\)) or on the current value (small \(\beta\)).

With \(\beta = 0.95\) 3:01:03:

\[ V_2 = 0.95\,V_1 + 0.05\,a_2 \]

The previous value gets far more importance than the current one. Plot \(a_1\) and \(a_2\) and the average moves only a little toward \(a_2\), so a jumpy series becomes a smooth curve. Because the average depends on the earlier values, Krish adds, it can also be used for forecasting.

The average keeps its whole history. Replace \(V_2\) inside \(V_3\) by its own formula 3:02:38:

\[ V_3 = \beta V_2 + (1-\beta)\,a_3 = \beta^2 a_1 + \beta(1-\beta)\,a_2 + (1-\beta)\,a_3 \]

With \(\beta = 0.95\) the weights are 0.9025, 0.0475 and 0.05. Not in the video: in general the value \(k\) steps back gets weight \((1-\beta)\beta^k\). The weights fall off as powers of \(\beta\), which is why the average is called exponentially weighted. As a rule of thumb it remembers about \(1/(1-\beta)\) values: 20 for \(\beta = 0.95\), 10 for \(\beta = 0.9\).

On the board Krish draws what this does to the optimizer's path 3:02:08. Without the average, each step heads wherever the newest noisy gradient points. With it, each step bends only gently toward the new direction, and the following steps are controlled the same way until the path reaches the global minimum. The noise is removed and the curve is smoothed.

3:03:08 3:03:40 the V formula 3:05:14 what it fixes 3:06:19 recap

The momentum update

Where does the average go? Into the derivative of the loss with respect to the weights 3:03:08. Replace \(\partial L/\partial w_{t-1}\) in the update by \(V_{dw}\), the exponentially weighted average of the derivatives:

SGD with momentum \[ V_{dw_t} = \beta\,V_{dw_{t-1}} + (1-\beta)\,\frac{\partial L}{\partial w_{t-1}}, \qquad w_t = w_{t-1} - \eta\,V_{dw_t} \]

The bias works the same way with \(V_{db}\); Krish writes the bias version when he reaches Adam. The gradients come from mini-batches.

\(V_{dw_t}\) is the value of the derivative at time \(t\): \(\beta\) times its previous value plus \((1-\beta)\) times the newest derivative. Not in the video, but it shows why this smooths the path: successive mini-batch gradients disagree in their sideways parts, which flip back and forth, and agree in the direction that leads toward the minimum. Averaging cancels the first and keeps the second.

What this fixes, in Krish's words 3:05:14: it reduces the noise, it works with mini-batches, and it converges faster. He likes to tell the optimizers as a story, each one patching a loophole in the previous one, and jokes that finding the next loophole is how you earn a PhD.

Interview tip from the recap 3:06:54: if you are asked what to do when the path of gradient descent is very noisy, the answer is to bring a smoothing factor (momentum) into the optimizer. Interviewers rarely ask for the equations; he teaches them so that the idea is understood.

Advantages

  • Reduces the noise of mini-batch SGD and smooths the path.
  • Faster convergence.

Disadvantages

  • The learning rate \(\eta\) is still fixed, the same for every step (the gap AdaGrad fills next).

Not in the video: libraries usually write momentum without the \((1-\beta)\): \(v_t = \beta v_{t-1} + \eta\,g_t\), \(w_t = w_{t-1} - v_t\), typically with \(\beta = 0.9\). That is the same method with the learning rate rescaled by \(1/(1-\beta)\). For the IIT Madras treatment, see Lecture 5 (lecture-05.html), which also covers Nesterov momentum.

3:07:26 3:09:08 high, then lower 3:10:47 the adaptive rate 3:12:27 α and why it shrinks the rate 3:15:41 the problem

AdaGrad: an adaptive learning rate

The next optimizer is AdaGrad, adaptive gradient descent. So far the learning rate \(\eta\) has been a fixed number in every optimizer. It controls the speed of convergence, and Krish asks whether it could change instead: high at the start, when the weight is far from the global minimum, and smaller and smaller as it approaches the minimum 3:09:08. "Adaptive" is the word for that.

AdaGrad keeps the update rule and replaces the learning rate by an adaptive one, \(\eta'_t\):

AdaGrad \[ w_t = w_{t-1} - \eta'_t\,\frac{\partial L}{\partial w_{t-1}}, \qquad \eta'_t = \frac{\eta}{\sqrt{\alpha_t + \epsilon}}, \qquad \alpha_t = \sum_{i=1}^{t}\left(\frac{\partial L}{\partial w_i}\right)^2 \]

\(\eta\) is the learning rate you choose, \(\epsilon\) a small positive number. Each weight has its own \(\alpha_t\), built from its own gradients.

Notation: on the board Krish names the new rate \(\eta\) and writes the original one as "learning rate"; here \(\eta\) is the original rate and \(\eta'_t\) the adaptive one. The audio does not say "root" when he writes AdaGrad's and RMSProp's denominators, but it does when he writes Adam's, \(\eta/\sqrt{S_{dw} + \epsilon}\). The standard AdaGrad and RMSProp rates have the square root, as written here.

The two new symbols:

  • \(\epsilon\) 3:11:54 is a small number that prevents division by zero. If \(\alpha_t\) were 0, \(\eta\) divided by it would be infinite; adding \(\epsilon\) keeps the denominator above zero. (Not in the video: typical values are \(10^{-8}\) to \(10^{-7}\).)
  • \(\alpha_t\) 3:12:27 sums the squared derivatives of the loss with respect to that weight over all time steps from 1 to the current \(t\).

Why does the rate go down? Every term in \(\alpha_t\) is a square, so \(\alpha_t\) can only grow from one step to the next 3:14:04. It sits in the denominator, so \(\eta'_t\) keeps decreasing as training goes on and the weight gets closer to the global minimum. Krish's illustrative numbers have \(\eta'\) falling from 0.01 at \(t = 1\) to about 0.002 by \(t = 3\). That is how AdaGrad brings adaptiveness into the learning rate: it is never fixed.

The problem 3:15:41

In a deep neural network the derivatives keep being added to \(\alpha_t\) step after step, so \(\alpha_t\) can become a huge number. Then \(\eta'_t\) becomes negligible. With an already small \(\eta\) such as 0.01 divided by a huge number, the update hardly changes the weight, and \(w_t \approx w_{t-1}\) 3:17:18. Learning stalls. AdaGrad also leaves out the smoothing that momentum brought: it uses the raw derivative.

Advantages

  • The learning rate adapts: large steps early, smaller steps near the minimum.
  • Each weight gets its own rate.

Disadvantages

  • \(\alpha_t\) only grows; in a deep network it can become huge, the rate becomes negligible and the weights stop changing.
  • No smoothing of the gradient (no momentum).

Not in the video: AdaGrad was designed for sparse features, whose weights see few nonzero gradients and so keep a larger rate. For the IIT Madras treatment, see Lecture 5 (lecture-05.html).

3:16:48 3:17:51 S_dw 3:18:58 β = 0.95 3:21:07 still no smoothing

AdaDelta and RMSProp: keep the rate under control

Krish covers AdaDelta and RMSProp together, saying the two have almost the same functionality. Both attack AdaGrad's problem: \(\alpha_t\) must not reach a huge value. The fix is to replace the running sum by an exponentially weighted average, so that its growth is controlled 3:17:51:

RMSProp (AdaDelta as presented in the video) \[ \begin{gathered} S_{dw_0} = 0, \qquad S_{dw_t} = \beta\,S_{dw_{t-1}} + (1-\beta)\left(\frac{\partial L}{\partial w_{t-1}}\right)^2, \\ \eta'_t = \frac{\eta}{\sqrt{S_{dw_t} + \epsilon}}, \qquad w_t = w_{t-1} - \eta'_t\,\frac{\partial L}{\partial w_{t-1}} \end{gathered} \]

With \(\beta = 0.95\) 3:18:58:

\[ S_{dw_t} = 0.95\,S_{dw_{t-1}} + 0.05\left(\frac{\partial L}{\partial w_{t-1}}\right)^2 \]

Each new squared derivative enters with weight 0.05 and the old ones keep fading, so \(S_{dw}\) never jumps up by a large amount. It follows the recent size of the gradients instead of piling them all up. The learning rate still decreases, but slowly and under control, and the weights keep moving toward the global minimum.

Still missing: smoothing 3:21:07

Look at the update again: it still multiplies the raw derivative \(\partial L/\partial w_{t-1}\). AdaGrad, AdaDelta and RMSProp make the learning rate adaptive, but none of them smooths the gradient the way SGD with momentum did with \(V_{dw}\). Combining \(V_{dw}\) with \(S_{dw}\) would solve both problems 3:21:39, and that combination is the next optimizer.

Advantages

  • Adaptive learning rate that does not collapse: \(S_{dw}\) stays near the recent squared gradient.

Disadvantages

  • No smoothing: the raw, noisy derivative is still used.

Not in the video: the two are not identical. RMSProp is exactly the rule above. AdaDelta keeps a second exponentially weighted average, of the squared weight updates, and uses its square root in place of \(\eta\), so it needs no learning rate at all. For the IIT Madras treatment, see Lecture 5 (RMSProp and AdaDelta in lecture-05.html).

Adam: momentum plus an adaptive rate

The Adam optimizer combines momentum, the exponentially weighted average of the gradients, with the RMSProp idea of an adaptive learning rate. Krish calls it currently the best optimizer, the one most people use and the one researchers recommend. Variants such as AdaMax exist.

Adam keeps four averages, all starting at 0: \(V_{dw}\) and \(V_{db}\) for the gradients of the weight and the bias, and \(S_{dw}\) and \(S_{db}\) for their squares 3:24:19. The weight and the bias are both updated with them:

Adam (as written in the video) \[ \begin{aligned} V_{dw_t} &= \beta\,V_{dw_{t-1}} + (1-\beta)\,\frac{\partial L}{\partial w_{t-1}}, & V_{db_t} &= \beta\,V_{db_{t-1}} + (1-\beta)\,\frac{\partial L}{\partial b_{t-1}}, \\ S_{dw_t} &= \beta\,S_{dw_{t-1}} + (1-\beta)\Big(\frac{\partial L}{\partial w_{t-1}}\Big)^2, & S_{db_t} &= \beta\,S_{db_{t-1}} + (1-\beta)\Big(\frac{\partial L}{\partial b_{t-1}}\Big)^2, \\ w_t &= w_{t-1} - \frac{\eta}{\sqrt{S_{dw_t} + \epsilon}}\,V_{dw_t}, & b_t &= b_{t-1} - \frac{\eta}{\sqrt{S_{db_t} + \epsilon}}\,V_{db_t} \end{aligned} \]

\(V_{dw_0} = V_{db_0} = S_{dw_0} = S_{db_0} = 0\).

While writing \(V_{db}\) Krish first multiplies the two terms and then corrects himself: they are added, as above. He writes a single \(\beta\) for all the averages.

This one update solves both problems of the story 3:27:00: the path is smoothed, as with momentum, and the learning rate is adaptive, as with RMSProp. Krish ends the session with the usual invitation: if you find flaws in Adam too, start writing a research paper.

Advantages

  • Smooths the noise (momentum's \(V\)).
  • Adaptive learning rate per weight that does not collapse (RMSProp's \(S\)).
  • The most widely used optimizer.

Disadvantages

  • None named in the video.
  • Not in the video: it stores two extra numbers per weight, has more hyperparameters, and on some problems well-tuned SGD with momentum generalizes better.

Not in the video: the published Adam (Kingma and Ba, 2015) uses two different decay rates, \(\beta_1 = 0.9\) for \(V\) and \(\beta_2 = 0.999\) for \(S\), and a bias correction. Because \(V\) and \(S\) start at 0, they are too small in the first steps, so Adam divides them by \(1 - \beta_1^{\,t}\) and \(1 - \beta_2^{\,t}\) before the update. The usual default learning rate is \(\eta = 0.001\). For the IIT Madras treatment, see Lecture 5 (Adam and bias correction in lecture-05.html).

All seven optimizers compared

Keras · choosing the optimizer and the batch size (added for these notes)

from tensorflow.keras import optimizers

# the update rule
opt = optimizers.SGD(learning_rate=0.01)                   # plain (mini-batch) SGD
opt = optimizers.SGD(learning_rate=0.01, momentum=0.9)     # SGD with momentum
opt = optimizers.Adagrad(learning_rate=0.01)
opt = optimizers.Adadelta(learning_rate=1.0, rho=0.95)
opt = optimizers.RMSprop(learning_rate=0.001, rho=0.9)
opt = optimizers.Adam(learning_rate=0.001, beta_1=0.9, beta_2=0.999)
model.compile(optimizer=opt, loss='mse')

# the batch size: n = len(X_train)
model.fit(X_train, y_train, epochs=100, batch_size=len(X_train))  # gradient descent: 1 iteration per epoch
model.fit(X_train, y_train, epochs=100, batch_size=1)             # SGD: n iterations per epoch
model.fit(X_train, y_train, epochs=100, batch_size=32)            # mini-batch SGD: n/32 per epoch

Keras's rho plays the role of \(\beta\) in RMSProp and AdaDelta, and beta_1, beta_2 are Adam's two decay rates. Its SGD momentum uses the library form without \((1-\beta)\) described under the momentum update. Write only one opt = … line in real code; they are stacked here for comparison.

Key terms

Optimizer
The rule that updates weights and biases during backpropagation to reduce the cost; each one modifies \(w_t = w_{t-1} - \eta\,\partial L/\partial w_{t-1}\).
Learning rate \(\eta\)
The step size of the update. Fixed in gradient descent, SGD, mini-batch SGD and momentum; adapted per weight in AdaGrad, RMSProp and Adam.
Epoch
One pass of all \(n\) training records through forward and backward propagation.
Batch size
The number of records used for one weight update: \(n\) for gradient descent, 1 for SGD, in between for mini-batch SGD.
Iteration
One forward pass, cost, backward pass and weight update on one batch. An epoch has \(n/\text{batch size}\) of them.
Gradient descent
All records in every update: one iteration per epoch and a smooth path, but a huge memory requirement.
Stochastic gradient descent (SGD)
One record per update: little memory, \(n\) iterations per epoch, slow and very noisy convergence.
Mini-batch SGD
A batch of records (e.g. 1,000) per update: moderate memory, \(n/\text{batch size}\) iterations per epoch, some noise.
Noise
The zigzag of the path to the minimum caused by gradients computed on part of the data. Highest for SGD, lowest for gradient descent.
Exponentially weighted average
\(V_t = \beta V_{t-1} + (1-\beta)a_t\). The value \(k\) steps back has weight \((1-\beta)\beta^k\), so large \(\beta\) means heavy smoothing.
SGD with momentum
Mini-batch SGD that steps along \(V_{dw}\), the exponentially weighted average of the gradients, instead of the raw gradient.
AdaGrad
Adaptive rate \(\eta/\sqrt{\alpha_t + \epsilon}\) with \(\alpha_t\) the sum of all past squared gradients and \(\epsilon\) a small guard against division by zero. The rate can shrink until learning stops.
RMSProp, AdaDelta
Replace AdaGrad's sum by an exponentially weighted average \(S_{dw}\) of squared gradients, so the rate stays under control.
Adam
Momentum's \(V_{dw}\) over RMSProp's \(\sqrt{S_{dw} + \epsilon}\): \(w_t = w_{t-1} - \eta\,V_{dw}/\sqrt{S_{dw} + \epsilon}\).

Test yourself

Q1A data set has 50,000 records. How many iterations does one epoch take with gradient descent, with SGD, and with mini-batch SGD at batch size 250? How many in 20 epochs?

Gradient descent: 1 per epoch, 20 in total. SGD: 50,000 per epoch, 1,000,000 in total. Mini-batch SGD: \(50{,}000/250 = 200\) per epoch, 4,000 in total. In all three cases each record is used once per epoch; only the number of records per update changes.

Q2Krish calls gradient descent resource intensive and SGD slow with high time complexity. Explain both, and where mini-batch SGD sits.

Gradient descent pushes all \(n\) records through one forward pass, so all of them must be in memory at once (huge RAM, GPUs), even though it makes just one update per epoch. SGD holds one record, but it needs \(n\) separate forward passes, backward passes and updates per epoch, each based on one noisy record, so it converges slowly. Mini-batch SGD holds one batch (e.g. 1,000 records), makes \(n/1{,}000\) updates per epoch and averages each gradient over enough records to keep the noise low.

Q3Compute the exponentially weighted average of \(a = (10, 14, 6, 12)\) with \(V_1 = a_1\), for \(\beta = 0.5\) and for \(\beta = 0.9\). Which is smoother?

\(\beta = 0.5\): \(V_2 = 0.5\cdot 10 + 0.5\cdot 14 = 12\), \(V_3 = 0.5\cdot 12 + 0.5\cdot 6 = 9\), \(V_4 = 0.5\cdot 9 + 0.5\cdot 12 = 10.5\). \(\beta = 0.9\): \(V_2 = 9 + 1.4 = 10.4\), \(V_3 = 9.36 + 0.6 = 9.96\), \(V_4 = 8.964 + 1.2 = 10.164\). The data jump by up to 8. With \(\beta = 0.5\) the average still moves by 3; with \(\beta = 0.9\) it stays between 9.96 and 10.4. The larger \(\beta\) is smoother.

Q4Unroll \(V_3\) with \(V_1 = a_1\). What weights do \(a_1\), \(a_2\), \(a_3\) get for \(\beta = 0.95\), and why is the average called exponentially weighted?

\(V_3 = \beta^2 a_1 + \beta(1-\beta)a_2 + (1-\beta)a_3\), so the weights are 0.9025, 0.0475 and 0.05, which add up to 1. In general the value \(k\) steps back gets \((1-\beta)\beta^k\): the weights decay as powers of \(\beta\), that is exponentially. The large weight on \(a_1\) comes from starting at \(V_1 = a_1\); it fades as \(\beta^{t-1}\).

Q5One weight's gradients over three iterations are 2, 1 and 1. With \(\eta = 0.1\) and \(\epsilon\) negligible, find AdaGrad's learning rate at each step, then RMSProp's with \(\beta = 0.95\) and \(S_{dw_0} = 0\).

AdaGrad: \(\alpha = 4, 5, 6\), so \(\eta' = 0.1/2 = 0.050\), \(0.1/\sqrt5 = 0.045\), \(0.1/\sqrt6 = 0.041\). It keeps falling although the gradients did not grow. RMSProp: \(S_1 = 0.05\cdot 4 = 0.2\), \(S_2 = 0.95\cdot 0.2 + 0.05\cdot 1 = 0.24\), \(S_3 = 0.95\cdot 0.24 + 0.05 = 0.278\), so \(\eta' = 0.224\), \(0.204\), \(0.190\). \(S\) moves only slowly, so the rate barely changes. (Here it is even above \(\eta\), because \(S\) started at 0 and is still small, the start-up effect Adam's bias correction removes.)

Q6Why can AdaGrad stop learning in a deep network, and what exactly do AdaDelta and RMSProp change to prevent it?

\(\alpha_t\) is a running sum of squares, so it never decreases. After many iterations it can be huge, \(\eta/\sqrt{\alpha_t + \epsilon}\) becomes negligible and \(w_t \approx w_{t-1}\). RMSProp (and AdaDelta as presented) replaces the sum by \(S_{dw_t} = \beta S_{dw_{t-1}} + (1-\beta)(\partial L/\partial w)^2\). Each new square enters with weight \(1 - \beta\) and old squares fade, so \(S_{dw}\) stays near the recent squared gradient and the rate does not collapse.

Q7Write Adam's updates for a weight and a bias. Which parts come from SGD with momentum and which from RMSProp? What does the published Adam add?

\(w_t = w_{t-1} - \eta V_{dw_t}/\sqrt{S_{dw_t} + \epsilon}\) and \(b_t = b_{t-1} - \eta V_{db_t}/\sqrt{S_{db_t} + \epsilon}\), with \(V\) the exponentially weighted average of the gradients (from momentum, in the numerator) and \(S\) that of the squared gradients (from RMSProp, in the denominator), all starting at 0. The published Adam uses \(\beta_1 = 0.9\) for \(V\), \(\beta_2 = 0.999\) for \(S\), and divides them by \(1 - \beta_1^{\,t}\) and \(1 - \beta_2^{\,t}\) to correct their start at 0.

Q8Interview question: "My mini-batch training is very noisy and slow to settle. What would you change?"

Krish's answer is to add a smoothing factor to the optimizer: use SGD with momentum (or Adam, which includes it). The exponentially weighted average of the gradients cancels the parts that flip from batch to batch and keeps the direction they agree on, so the path stops zigzagging. From the earlier comparison, a larger batch also reduces the noise, at the cost of more memory per update.
